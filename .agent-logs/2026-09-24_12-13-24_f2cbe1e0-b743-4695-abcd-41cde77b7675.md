## Issue found and fixed

**React hydration mismatch** when reading `localStorage` on the client but not on the server:

- Valid remix URLs could briefly render **“No library item with that id”** on the server, then switch to **“Remix loaded…”** on the client (this matched the dev overlay hydration warning on `/image`).
- Library grid and `/library/[id]` had the same class of problem (empty / “not found” on SSR vs real data after hydrate).

**Fix:** `useClientHydrated()` gates library/remix UI until after the hydration pass. Library list and recipe detail show a short **“Loading…”** state first.

Files touched: `src/hooks/use-client-hydrated.ts`, `LibraryPageClient`, `LibraryGenerationDetailClient`, `ImageComposer`.

Tests and lint still pass.

## Edge cases (acceptable / documented)

| Case | Behavior |
|------|----------|
| **Reference image on remix** | Only filename is stored; file is not restored (by design). UI tells user to re-attach. |
| **Remix after user edits fields** | `remixAppliedRef` + page `key` prevent re-applying on every render; changing `?remix=` remounts composer. |
| **`?preset=` + `?remix=`** | Remix wins; preset is ignored (intentional). |
| **Soul v2 in recipe** | Shown in recipe panel; remix restores `modelId`; demo path unchanged until Phase 7. |
| **Effect preset on remix** | `effectPresetId` is kept on **new** saves via `recipeEffectPresetId`; composer does not show the preset banner (only library/effect name in recipe). |
| **Share recipe URL** | `/library/[id]` only works on the device/browser that has that id in `localStorage`. |
| **Invalid / cleared storage** | Honest empty or not-found states. |
