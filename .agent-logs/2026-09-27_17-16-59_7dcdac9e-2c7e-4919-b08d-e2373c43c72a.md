## Issues found (and fixed)

| Issue | Risk | Fix |
|--------|------|-----|
| **Auth vs library race** — `user` was set before cloud mode, so Library could briefly use guest merge (showcase + `localStorage`) while “signed in” | Wrong tiles / wrong detail resolution | Library UI now keys off **`cloudMode`** from the library store, not `user`. `setStudioLibraryAuthedMode(true)` runs **before** `setUser`. |
| **Import cleared `localStorage` on any 200** — including all DB failures (`imported: 0`, `skipped: N`) | Guest library wiped with nothing in cloud | Clear local only when **`skipped === 0`** (every row processed successfully). |
| **Import cleared on partial failure** (some rows threw) | Lost items that never reached Postgres | Same rule: partial failure keeps `localStorage`. |
| **Parallel `handleSignedIn`** (`getUser` + `onAuthStateChange`) | Double import / flicker | Single in-flight promise guard. |
| **`onAuthStateChange` + async work** | Supabase deadlock risk | Deferred sign-in work with `queueMicrotask`. |
| **Cloud library not loaded before demo dedupe** | `excludeOutputUrls` empty → repeat demo URLs | Image (and video demo) **await `refreshAuthedStudioLibrary()`** when `cloudMode && !hydrated`. |
| **Video demo ignored library URLs** | Pre-existing gap; worse with cloud library | Demo video POST now sends **`excludeOutputUrls`**. |
| **Stale cloud snapshot on re-login** | Old items flash | Turning cloud mode **on** resets snapshot + `hydrated` until fetch completes. |

`npm test` (61) and `npm run build` both pass after these fixes.

## Remaining edge cases (no code change — worth knowing)

1. **Partial import + `localStorage`** — If some rows fail import and some succeed, we keep the full local key so nothing is lost. Next sign-in may re-import; dedupe by `output_url` should avoid duplicate tiles, but you might see extra API work.

2. **Re-import when everything was already in cloud** — Upserts succeed with `skipped === 0`, so local is cleared even when `imported` counts bumps, not new rows. That’s intended.

3. **No “Save to library” retry UI** — If `POST /api/library` fails after a successful job, `savedToLibrary` stays false (plan mentioned a retry button; not built in v1).

4. **Login callback errors** — `/login?error=auth_callback` isn’t surfaced in the UI yet.

5. **Cap trim races** — Two rapid saves could briefly exceed 48 rows before trim; unlikely in normal use.

6. **Manual Supabase setup** — Wrong RLS, redirect URLs, or unconfirmed email still surface as empty library / 401; needs dashboard checks in [`docs/SUPABASE.md`](docs/SUPABASE.md).

7. **Next.js 16 middleware deprecation** — Build warns to migrate to `proxy`; behavior is fine today, not a functional bug.
