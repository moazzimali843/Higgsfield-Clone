## Issues found (and what we did)

### 1. Stale composer when `preset` changes (fixed)

`ImageComposer` only read `initialValues` on first mount. Same route with a different `?preset=` (browser back/forward, or future in-app links) could show the **previous** prompt/settings.

**Fix:** `key={presetId ?? "blank"}` on `ImageComposer` so React remounts when the preset changes.

### 2. `searchParams.preset` as an array (fixed)

Duplicate keys (`?preset=a&preset=b`) can arrive as `string[]`. Passing that into `.trim()` would throw.

**Fix:** `firstQueryValue()` in `src/lib/search-params.ts`, used on the image page; tests added for trim, empty, and array cases.

### 3. Bad `modelId` in preset JSON (hardened)

A typo in preset data could leave the model `<select>` in a broken controlled state.

**Fix:** Resolve preset → `getComposerModelById(...) ?? "demo"`.
