## High priority

### 1. Vercel / serverless timeout vs 120s polling

`pollHiggsfieldUntilTerminal` can run up to **~120s** in one `POST /api/higgsfield/image` handler. On Vercel, default function limits are often **10s (Hobby) or 60s (Pro)** unless you set `maxDuration`.

**Edge case:** The platform kills the function → the browser may see a generic failure (not your JSON fallback). Meanwhile Higgsfield may still **complete the job and charge** if submit already succeeded.

**You may need to:** set `export const maxDuration = …` on that route (Pro plan), or shorten polling / move polling to the client via a follow-up route (bigger change).

### 2. Timeout / fallback vs billing

Whenever **submit succeeds** but we **timeout** or **demo-fallback**, credits may still be spent on Higgsfield’s side while the UI shows a demo image. That is the hardest edge case in this design.

### 3. Mixed credentials (UI + env)

`resolveHiggsfieldCredentials` does:

- `keyId = input.apiKeyId || env.HIGGSFIELD_KEY_ID`
- `secret = input.apiKeySecret || env.HIGGSFIELD_KEY_SECRET`

**Edge case:** User fills only **Key ID** in the UI and the server has `HIGGSFIELD_KEY_SECRET` → ID and secret can be from **different pairs** → confusing **401** and then **demo fallback** (looks like “API broken”).

Safer rule: if **either** UI field is non-empty, **both** must come from the UI; env only when **both** UI fields are empty.

### 4. `status_url` not validated (SSRF hygiene)

We poll whatever `status_url` Higgsfield returns. In normal operation that is fine. For a thin BFF, it is safer to only poll URLs on `api.higgsfield.ai` (or relative `/requests/...` paths).

---

## Medium priority

### 5. Plan vs UX: estimate before real submit

Phase 7.1 says show estimate **before** real submit. The UI has **Estimate cost**, but **Generate (Soul v2)** does not require it. Easy to skip and spend credits unknowingly.

### 6. Estimate ignores reference image

Estimate uses prompt + aspect only. With a reference attached, the real job uploads and may send `image_url`; **credits/USD can differ** from what was shown.

### 7. Reference / `image_url` (7.3)

Soul v2 Standard’s [API reference](https://open.higgsfield.ai/models/higgsfield-ai/soul/v2/standard/api-reference) does **not** list `image_url`. We still set `usedReferenceUpload: true` after upload even if the model ignores the field.

**Edge cases:**

- API returns **400** on submit → **502** to client (no demo fallback) — reasonable.
- API accepts job but ignores reference → UI overstates reference effect.

### 8. Public deploy + server env keys

If `HIGGSFIELD_KEY_ID` / `HIGGSFIELD_KEY_SECRET` are set on a **public** Vercel project, anyone who picks Soul v2 can use **your** credits without pasting keys (empty form + server env). README says env is for local testing — worth treating as **ops policy**, not a code bug.

### 9. Library + expired real URLs

Real URLs can die after ~7 days. Retention is shown at generation time only; **library cards** do not warn about expiry (broken thumbnails later).

### 10. Non-auth HTTP errors on submit

**400** (bad body), **429**, etc. → **502** and **no** demo fallback. That is usually correct (don’t mask a bad request with a demo), but reviewers may see a hard error instead of fallback.
