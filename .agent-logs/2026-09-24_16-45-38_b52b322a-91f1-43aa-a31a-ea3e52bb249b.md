## Medium: worth knowing before QA

**1. Remix routing (documented in plan)**  
Video library items still open **Image** composer (`/image?remix=…`). Recipe loads, but `modelId` may be `seedance-2.5` while the image model picker only knows Soul/Demo. User can still generate on Demo/Soul; video model id in state is confusing.

**2. Two “remix” paths on library grid**  
Grid link uses `imageComposerHrefFromRecipe` (query params). Detail uses `composerHrefForRemix` (library id). Video/Seedance recipes from the grid may **drop** `modelId` because `getComposerModelById` only knows image models. Detail remix is more faithful.

**3. Soul cost estimate vs server env**  
“Estimate cost” still **requires** keys in the UI. Soul/Seedance **generate** can use `.env.local` with empty UI fields. Local dev-only inconsistency (mostly pre-existing for estimate).

**4. API key session vs typing**  
Keys in the header/composer work in memory immediately; **“Save for session”** is what writes `sessionStorage`. Typing without save is lost on full tab close. Matches the plan but easy to misunderstand.

**5. API key hydrate race (low)**  
If someone edits keys in the first instant before the provider’s `useEffect` loads session storage, load could overwrite typing. Unlikely in practice.

**6. Seedance / Higgsfield API (needs your keys)**  
Not exercised from this environment. Risks to validate manually:

- Completed payload might not match `video: { url }` (would trigger labeled demo fallback).
- `status_url` on another host would still be blocked (only `api` + `platform` allowlisted).
- CDN playback in `<video>` may fail (CORS); grid/detail would show a broken player with no download fallback.

**7. Library detail copy**  
Header still says remix goes to “image composer” even for video items. Accurate for code today, misleading for video-only workflows.
